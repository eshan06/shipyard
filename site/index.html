What it does

Preview environments that include the whole stack

Most preview tools deploy a frontend. Real review needs the services behind it — a database with believable data, a cache, background workers.

🚀

Automatic, per pull request

A GitHub webhook opens an environment when the PR opens, redeploys it on every push, and destroys it on close. No one files a ticket for a staging slot.

🗄️

Full stack, seeded

Web, API, Postgres, Redis and workers come up together, with seed templates loading believable data so the environment is worth clicking through.

🔐

Built for untrusted code

Previews run code from any contributor's branch, so containers drop Linux capabilities, get CPU/memory/PID quotas and a read-only root, on a per-preview network.

💸

Cleans up after itself

Idle previews auto-stop, closed PRs are reaped on a TTL, and per-preview usage rolls up to dollars against a team budget — so the bill can't drift.

How it works

Webhook in, live URL out

01

PR opened

A signed GitHub webhook hits the control plane, which records the PR and queues a deploy.

02

Stack planned

The planner turns the repo's config into a container graph and resolves it in dependency order.

03

Built & started

Workers build images and start containers, streaming logs to the dashboard as it happens.

04

Routed & reaped

A reverse proxy maps <slug>.preview.you.dev to the stack — until it goes idle.

Real-time

Watch a deploy happen

Build and runtime logs stream from the worker to your browser over server-sent events. Status changes land the moment they happen, so a deploy is something you watch rather than something you refresh.

  • ✓ One-click redeploy, stop and destroy

AI code review

A first-pass reviewer on every diff

A Python service consumes the same PR events, analyses the diff for security, correctness and style issues, and posts its findings back to the pull request — so the humans start from a shorter list.

  • ✓ Pluggable backends — Claude, a local Ollama model, or offline
  • ✓ Findings grounded in the diff, so it can't invent files
  • ✓ Bounded prompts and capped findings to control spend

Terminal

Or stay in your shell

A dependency-free Go binary talks to the same API as the dashboard, with scoped tokens for CI. List previews, tail logs, trigger a redeploy — without leaving the terminal.

  • ✓ Live log tailing over the same SSE streams
  • ✓ --json output for scripting and CI
  • ✓ Team-scoped API tokens with explicit scopes

Under the hood

Built like production infrastructure

A typed monorepo with a real state machine, durable queues, and the operational surface you'd want if this were running for a team.

Correct under concurrency

Every status change is a compare-and-swap against an explicit state machine, so racing deploys, teardowns and retries can't corrupt a preview's state.

Operable

Prometheus metrics on the API and worker, health and readiness probes, structured logs, encrypted secrets at rest, and Compose plus Kubernetes manifests.
