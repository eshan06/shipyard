## 3. The Service

### 3.1 Description

The Service is a hosted, business-to-business "preview environments manager". For each connected Customer Repository, on qualifying pull-request or branch events, the Service:

(a) receives webhook events from GitHub (repository metadata, pull-request events, commit SHAs, branch names) through the GitHub App;
(b) clones and builds the relevant Customer Code;
(c) provisions and **runs** the resulting application stack — which may include web, API, database, cache, and worker components — inside isolated, containerized, ephemeral Preview Environments (orchestrated via Docker / Kubernetes);
(d) injects Customer-supplied Environment Variables and Secrets into those environments at runtime;
(e) returns a shareable preview URL and surfaces deploy status, build and runtime logs, reviewers, and cost/usage metrics through the dashboard; and
(f) tears down Preview Environments automatically (for example, on idle timeout or when the pull request is closed).

### 3.2 Execution of Customer Code

(a) the Service will execute software, build steps, and processes defined by Customer Code, which may be arbitrary and which Shipyard does not author, review, or control;

(c) responsibility for Customer Code rests entirely with Customer, as set out in Sections 5 and 14, and Shipyard's liability for the behavior of Customer Code is disclaimed and limited as set out in Sections 13 and 15.

Shipyard will use commercially reasonable efforts to isolate Preview Environments from one another and from Shipyard's control plane (see Section 10), but no isolation is perfect, and Customer must not rely on the Service to contain code that is malicious, unstable, or designed to escape containment (see Section 6 and the AUP).

### 3.3 Ephemeral by design
